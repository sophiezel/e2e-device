# Agent/脚本双层决策模型

将测试流程中的决策拆分为两层：脚本负责确定性逻辑，Agent 负责需要交互/判断的逻辑。
脚本输出结构化数据驱动 Agent，Agent 的决策结果回传给脚本执行。

## 为什么这样做

Hybrid E2E 测试中存在两类截然不同的操作：
- **确定性操作**：adb 连接检测、设备信息采集、chromedriver 匹配、spec 生成、wdio 执行、覆盖率计算。这些不需要主观判断。
- **需要上下文的操作**：多条配置候选的引导确认、从需求文档理解验收场景、测试范围的确认、失败根因诊断。

把全部逻辑塞进脚本 → 脚本需要处理自然语言交互，不可行。
把全部逻辑推给 Agent → Agent context 被流程性细节淹没，token 浪费。
双层模型让每个角色做它最擅长的事。

## 替代方案

- **纯脚本驱动**：`init.sh` + `orch_cli` JSON 驱动 Agent 做翻译。问题：无法处理需要理解上下文的决策（如多条 domain 候选交叉验证、从文档自然语言提取 case）。
- **纯 Agent 驱动**：Agent 直接调 adb/appium/wdio。问题：Agent 每轮 turn 都要载入冗长的工具输出，对话膨胀快，容易"lost in the middle"。
